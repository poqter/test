# HWARANG 1.19.0 적용 안내

운영 1.18.0을 기준으로 수정한 소스 패키지입니다. 사이트에 배포하거나 운영 SQL을 실행하지 않았습니다.
빌드: hwarang-2026.10.15-platform-v72-learning-recovery / 브리핑 엔진: 1.12.9-editorial

## 먼저 확인할 사항
- 아카데미는 교육 상위 앱이며, AI 상담 시뮬레이터는 그 안의 하위 기능입니다.
- 전체 ZIP과 변경 ZIP 중 하나만 적용합니다. 변경 ZIP은 1.18.0 기준입니다. 1.12.7에 덮어쓰는 변경 패키지가 아닙니다.
- 이미 적용한 SQL 23·24는 다시 실행하지 않습니다. 특히 23은 기존 테이블을 생성하는 스크립트입니다.
- 이번에는 SQL 25·26이 추가됩니다. 소스 파일만 올려서는 교육 저장소와 새 복구 메뉴가 작동하지 않습니다.
- 기존 미확인 요청은 자동 해제하지 않습니다. 동일 요청을 자동 재호출하지 않으며 공급자 비용을 0원으로 처리하지 않습니다.

## 적용 순서
1. 현재 저장소와 Supabase 데이터베이스를 백업합니다. 직접 수정한 소스가 있다면 이번 변경 목록과 먼저 병합합니다.
2. Supabase SQL Editor에서 `25_Studio_Recovery_Operations.sql` 전체 실행 → `26_Academy_Learning.sql` 전체 실행 순서로 적용합니다. 이 두 파일은 재실행해도 기존 자료를 덮어쓰지 않도록 구성했습니다.
3. 기존 차단 요청 1건을 해제하려면 SQL 묶음의 `HWARANG_RELEASE_ONE_PENDING_REQUEST.sql`을 실행합니다. 해당 사용자·요청 ID·상태·원장을 확인하고 일치하는 건만 처리합니다. 상태가 달라 중단되면 조건을 삭제하지 말고 관리자 화면에서 해당 요청을 다시 확인하세요. 이미 같은 복구 이력이 있으면 다시 차감하거나 복구하지 않습니다.
4. 전체본 또는 변경본을 프로젝트 루트 구조 그대로 적용하고 GitHub에 반영합니다. 새 education 폴더, frontend 파일, SQL, STAGE1_CHANGED_FILES.json까지 함께 올립니다.
5. WORKSPACE·ACADEMY·CALCULATOR 세 앱에 반영됐는지 빌드 ID를 확인하고 필요한 앱을 재시작합니다. Secrets의 기존 URL·키·AI 설정은 유지합니다.
6. 관리자 → 학습 AI에서 보류 목록을 확인합니다. 상담 사용자는 기록을 다시 열거나 ‘저장된 상담 상태 새로고침’을 눌러 새 버전을 불러옵니다.
7. 아래 운영 확인 목록을 순서대로 점검합니다. ZIP을 제공한 사실과 운영 반영 완료는 서로 다릅니다.

## 반영한 주요 내용
- AI 요청: 동일 사용자 내 여러 상담의 요청을 DB에서 직렬화. 다른 사용자 요청을 전역 잠금하지 않음. 10분 이상 지난 미확인 요청의 관리자 복구, 원장 예약 해제, 비용 미확인 보존, 감사 기록, 중복 복구 방지, 늦은 응답 재반영 차단. 완료/만료된 차감은 임의 환불하지 않음.
- 관리자: Studio 보류·실패·비용 미확인을 대시보드에 연결. 상태 조회 실패를 정상으로 표시하지 않음. 기록된 비용과 실제 총비용을 구분. 기존 엔진 정책과 실제 Studio 모델 설정 안내를 구분.
- 상담 화면: 진행 중 기록 선택을 작은 메뉴로 이동. 고객/채팅/도움 구조와 입력창 유지. 기록 전용 진입은 목록 표시. 저장 상태 새로고침, 최근 고객 응답·전사·음성 생성 시간을 구분해 표시.
- 고객 역할·종료·평가·공유: 기존 역할 검증, 종료 발화 처리, 근거 기반 평가와 공식 평가 도움 차단, 선택 공유·공유 취소를 보존하고 회귀 검사. 기술 실패는 제출 답변으로 평가하지 않음.
- 아카데미: 4개 기초 과정, 12개 학습 항목, 학습용 자가 점검, 본인 진도 저장, 나의 학습, 과정 후 상담 연습 연결. 자격 인증 과정이나 완성된 장기 교육 커리큘럼으로 표시하지 않음.
- 자료실: 3개 자체 학습 노트, 분류·검색·본문 열람·다운로드. 최고관리자의 자료 등록/개정/게시/비공개, 기준일, PDF/TXT/MD 첨부(2MB). 자료실 및 교육별 기존 권한을 서버에서 확인. 개인 학습 진도는 관리자에게 제공하지 않음.
- 계산기: PC 2열·모바일 1열, 긴 제목과 설명을 위한 영역, 현재 탭/새 탭 버튼 유지. 이월결손금 빈 표는 공제 0건으로 처리하고 표·조건·계산·출력에 같은 입력 사용.
- 금융 비교: 동일 납입 기간·10년 시점 자산 비교, 적금 만기 원금과 세후이자 재운용 선택, 양쪽의 가정 세율·총납입·손익 표시. 갱신 비교의 확정 절감처럼 보이는 문구를 입력 가정에 따른 차이로 수정.
- 워크스페이스: 원수사 검색 최상단·사이드바 메뉴 검색 유지. 소개 영역 높이 축소, 실제 최근 사용·세션 즐겨찾기 추가. 밝은 브랜드와 이모지, 절제된 전환, 키보드 포커스·움직임 줄이기 지원.

- 실손 비교: 현재 보험료와 비교안의 추정/실제 입력 근거를 결과에서도 표시. 기존 산식과 세대 기준을 새 법령 기준으로 임의 변경하지 않음.

전체 제안 30개가 운영 검증까지 완료됐다는 의미는 아닙니다. 상세 범위는 `IMPLEMENTATION_SCOPE_1.19.0.md`에 구분했습니다.
- 실제 AI로 5개 장면 완주, 고객의 자연스러움·반복 답변·평가 근거, 텍스트/음성/혼합 사용과 정산 확인.
- 두 계정의 동시 실제 API 응답, 다중 탭·장시간·연결 끊김·재접속 확인. 현재 검증은 DB 사용자 격리와 오프라인 중복 방지입니다.
- 운영 파일로 교육 자료 등록→직원 검색/다운로드→개정 공개, 관리자/직원/타 조직 계정 권한 확인.
- 컨벤션·썸머·매니저·수수료의 실제 익명 원본 파일과 수기 정답 대조. 이번에 해당 지급 규칙과 기간 산식을 임의 변경하지 않았습니다.
- 보험사별 서식 확대, 외부 로그인 27개·공식 자료 최신성, 세법·실손 기준 최신성 확인. 미확인 자료를 최신 검증 자료로 표시하지 않습니다.
- 브리핑의 다음 생성 결과와 중복 감소, 원문 대조, 실제 모델 단가·과금 기록 대조. 이미 게시된 자료는 소스 교체만으로 재작성되지 않습니다.
- 자료실의 기본 노트와 과정은 시작용 콘텐츠입니다. 조직 전용 상품·보장 자료와 정규 교육 콘텐츠는 관리자가 추가해야 합니다. 현재 관리자 편집 기능은 자료실용이며 과정 편집은 소스/콘텐츠 개정 절차를 사용합니다.

## 운영 확인 순서
1. 관리자 대시보드가 보류 상태와 비용 미확인을 구분하는지 확인.
2. 기존 미확인 요청 복구 후 사용자 상담 새로고침, 1문장 전송, 약속 합의·종료, 평가·선택 공유 확인.
3. 서로 다른 두 계정에서 동시에 상담 진행. 한 계정의 대기 상태가 다른 계정을 막지 않는지 확인.
4. 음성 인식 문장 수정→전송→고객 음성 재생·일시정지→텍스트 전환 및 사용량 확인.
5. 아카데미 한 과정 완료 후 재로그인해 진도 확인. 비공개 자료가 직원에게 보이지 않는지 확인.
6. 계산기 PC 2열/모바일 1열, 빈 결손금 표/예시/초기화/PDF, 금융 비교 가정 변경 확인.
7. 각 업무 도구에 익명 파일 적용 후 화면 합계와 출력 파일 대조. 다음 브리핑 게시 날짜·상태 확인.

## 되돌리기
소스 문제가 있으면 백업한 1.18.0으로 되돌릴 수 있습니다. SQL 25·26은 데이터 삭제를 하지 않는 추가 변경이므로 무조건 DROP하지 마세요. 복구한 요청과 감사 기록·자료·진도는 유지합니다. 특정 건의 기존 차감이나 공급자 비용을 되돌려야 하는 경우 원장 확인 후 별도 조정이 필요합니다.
