## 1. 제품 목표와 문서 우선순위

전날과 당일의 다양한 주요뉴스를 모아 짧게 요약하고, 경제·금융은 지표와 해설로 흐름을 이해하게 한다. 설계사는 관련 이슈에서만 상담을 준비하고 고객은 공유 링크에서 편하게 읽는다.

개발 기준은 최신 사용자 확정사항 → 이 IMPLEMENTATION_SCOPE → ENGINE → NEWS/INSURANCE/MARKET Profile 순서다. 이 묶음의 5개 문서를 기존 개발 명세와 교체한다. 과거 통합 명세·체크포인트는 이력으로 보존하며 새 기준보다 우선하지 않는다.

## 2. 콘텐츠와 수량

| 영역 | 1차 기준 | 화면 |
|---|---|---|
| NEWS 종합뉴스 | 총 최대 10건, 대표 핵심 최대 1건 포함 | 대표 카드 → 다른 뉴스 제목·1~2문장 요약·출처·날짜·원문 |
| MARKET 경제·금융 | 지표 6개 + 전체 흐름 3~5문장 + 기사 총 6~8건 목표 | 지표 → 오늘의 흐름 → 대표 기사 → 다른 기사 → 필요한 해설 |
| INSURANCE 보험업계 | 실제 보험·GA 업계 기사와 필요한 영향·상담 | 대표 최대 1개 강조 → 기사 목록 → 관련 상담 준비 |
| 고객 | 경제·금융 + 국내 주요뉴스 + 승인된 보험 생활정보 | 간단한 소개와 읽기 화면 |
| 설계사 내부 | 위 정보 + 전체 보험업계·상담 준비·관련 도구·운영 정보 | 기존 WORKSPACE 권한 유지 |

NEWS는 대표가 있으면 1+9, 없으면 관련 최대 10건이다. MARKET의 대표 최대 1건은 기사 총 6~8건에 포함한다. 지표와 전체 흐름 해설은 기사 수가 아니다. 적격 기사가 적으면 실제 확보한 수량만 제공한다.

보험업계의 새 총 기사 수는 별도 확정되지 않았다. 기존 1.7.7의 CORE 8 / 관련 7은 분석 호환 상한으로 보존하되 매일 채울 할당량으로 새로 확정하지 않는다. 대표 카드 수와 내부 CORE 분류 수를 혼동하지 않는다.

같은 사건의 여러 기사·공문은 한 카드에 근거를 합친다. 고객 통합 화면에서도 주 섹션에 한 번 배치하고 필요하면 다른 섹션에서 연결한다.

## 3. 뉴스 수집

- 수집 구간: **전날 00:00 KST부터 해당 생성의 수집 마감까지**.
- 다양한 종합·통신·방송·경제·보험 전문언론을 포함한다.
- 허용된 공개 RSS/구조화 피드 우선, 필요한 원문 날짜·근거 보강, 부족한 분야에 제한된 기존 web_search.
- 공공기관 자료는 제도·수치 확인에 활용한다. 필수 기관 기사 비율이나 공식 Lane을 강제하지 않는다.
- Source의 수집 경로와 실제 발행사를 구분한다.
- 카테고리·발행사 편중을 점검하되 낮은 품질 기사로 숫자를 채우지 않는다.
- 기사 전문·사진을 재게시하지 않고 짧은 독립 요약과 원문 링크를 제공한다.
- 무료 API 여부와 AI 입력·고객 표시 가능 여부는 별도로 확인한다.
- 발행일 미확인·구간 밖·새 사실 없는 과거 재보도는 정상 일간 목록에서 제외한다.
- 수집 실패를 “오늘 중요한 뉴스 없음”으로 표시하지 않는다.

이 구간이 과거 36시간 CORE / 96시간 LIGHT 규칙을 대체한다. 지표의 거래일과 기사 발행일은 별개다.

## 6. 공유 발신자와 외부 정책

발신자는 링크 생성 당시 로그인한 설계사다. 서버가 계정의 display_name과 job_title을 읽는다. 관리자 권한명으로 직책을 대체하거나 이름을 하드코딩하지 않는다.

OG는 날짜·짧은 핵심 문장 중심의 간결한 카드로 구성한다. 이름 뒤에 실제 직책을 읽을 수 있게 표시하고 화랑은 보조 브랜드로 둔다. 로그아웃·전달 링크·다른 열람자로 이름이 바뀌지 않는다. 본문·OG·고객 PDF의 발신자와 날짜·판본이 일치한다.

생성 Snapshot의 external_share_allowed 기본 false는 유지한다. 조직의 외부 자동 공유 정책을 관리자가 한 번 활성화한 뒤 published + validation=ok + 외부 QA + 표시 권한을 통과한 본문만 자동 허용할 수 있다.

정상 승인된 외부 Payload가 기본 공유 구성이다. 매일 설계사가 모든 기사를 다시 편집·승인하는 작업을 강제하지 않는다. partial·미검증·hidden은 외부 차단한다.

내부 상담·점수·전략·비용·운영 로그·개별 고객·권한·키·WORKSPACE 메뉴는 외부 DTO에서 제외한다. 보험업계 전체 대신 승인된 생활 관련 정보만 고객에게 제공한다.

서버의 비로그인 HTTP HTML에 OG를 반환한다. Streamlit 로그인 세션·클라이언트 JS만으로 미리보기를 구현하지 않는다. 링크 회수·숨김·정정은 서버에서 적용한다. 이미 받은 메시지·카카오 캐시·다운로드 PDF의 완전 회수는 보장하지 않는다.

실제 수집·게시 시각을 기록한다. 저비용 Scheduler는 지연될 수 있어 엄격한 정시 SLA를 보장하지 않는다. 성공한 단계를 재사용하고 중복 유료 전체 생성을 막는다.

휴일 뉴스도 같은 구간을 사용한다. 지표는 마지막 확인 거래일/관측일을 표시한다. 이전판을 오늘 날짜로 바꾸지 않는다. 수동 정정·숨김·교체는 필수이며 상시 장중 자동 재생성은 후속이다.

Profile별 게시 Gate는 독립이다. 필수 지표가 누락된 MARKET은 partial이며 정상 외부 MARKET으로 공개하지 않는다. 정상 NEWS는 별도로 내부 게시할 수 있다.

## 9. 사용자 확인과 완료

Codex가 반복 코드·UI·PDF·회귀·권한 검수를 담당한다. 사용자는 다음 세 묶음을 확인한다.

R01~R12와 지표 공급원/표시 계약, A/B/C가 통과해야 출시 완료다. 상세는 BRIEFING_RELEASE_ROADMAP.md를 따른다. 방향 변경 시 정확한 변경 MD·코드 파일·이유·비용 영향을 먼저 안내하고 명세를 갱신한다.
