# 화랑 보험업계 명세 — INSURANCE V1.8.0

- 2026-10-08 / Asia/Seoul.
- 범위·수량·일정은 BRIEFING_V1_IMPLEMENTATION_SCOPE.md, 공통 계약은 BRIEFING_ENGINE_SPEC.md.
- 설계 기준이며 운영 완료를 의미하지 않는다.

## 1. 목적·범위

보험·GA 업계의 전날·당일 실제 기사와 관련 영향을 짧게 읽고, 관련성 있는 사건에서만 상담을 준비한다. 공문 모음·모든 뉴스의 판매 행동 변환을 목표로 하지 않는다.

| 분야 | 예 |
|---|---|
| 보험사·GA·시장 | 인수/합병·시장 진출·채널·경영 |
| 상품·보험료 | 실제 보장·보험료·갱신 변화, 단순 광고 제외 |
| 보험금·보상 | 실손·청구·지급·분쟁·판결·절차 |
| 소비자·보건 | 의료 이용·감염병·소비자 보호의 보험 관련성 |
| 보안·운영 | 보험사/GA 해킹·유출·전산 장애 |
| 제도·규제·세제 | 규제·준법·세금·연금 변화 |
| 참고·통계 | 의미 있는 업계 동향 |

언론·보험 전문매체를 주요 탐지망에 포함한다. 금융위·금감원·협회·보험사 발표는 규정/시행일/수치 확인에 활용하고 기사 비율을 강제하지 않는다.

## 2. 수량·선별

대표 최대 1개를 강조하고 나머지 적격 업계 기사는 짧은 목록으로 읽는다.

보험업계의 새 총 수량은 별도 확정되지 않았다. 기존 1.7.7 CORE 8 / 관련 7은 분석 호환 상한이며 매일 채울 수량·고객 공개 수량이 아니다. 실제 적격 수량을 표시한다.

중요도·Evidence·CORE/LIGHT는 내부용. 높은 점수로 검증 실패를 무시하지 않는다. 같은 사건의 여러 기사/공문은 한 Event의 근거로 묶고 대표/관련/고객 섹션에서 반복 계산하지 않는다.

## 3. 수집·날짜

구간: **전날 00:00 KST부터 해당 생성의 수집 마감까지**. 정규 마감 07:30 / 공개 08:00 목표. 휴일도 적격 뉴스가 있으면 제공한다.

허용된 언론 RSS/피드 → 날짜/근거 보강 → Coverage 부족·고위험 확인에 제한된 기존 web_search. 일반 매체 피드 전체를 보험으로 라우팅하지 않는다.

원문 발행일과 제공일·수집일 구분. 미확인·구간 밖·새 사실 없는 재보도 제외. 배경은 날짜 표시 상세로만 연결. 기사 전문/사진 재게시·유료벽/차단 우회 없음. 세 Profile 수집·Event를 재사용하고 기사당 독립 AI 호출하지 않는다.

## 4. 요약·영향

기본 요약 1~2문장. 필요한 기사에만 왜 중요한가/누구에게 영향/먼저 확인할 점을 추가한다.

- 해킹 시도와 실제 유출 확정 구분.
- 검토/예고/확정/시행 구분.
- 보험료 변화의 상품·세대·갱신·대상·시점 확인.
- 개별 계약의 지급·해지·전환·세제 효과를 확정하지 않음.
- 기사에 없는 약관·금액·의학적 사실을 만들지 않음.
- 상충 내용 병기·검증, 미확정 고위험의 고객 단정 차단.
- 회사 M&A 등 상담 관련 없는 업계 뉴스는 간단한 요약으로 종료.

## 5. 내부 읽기·상담

날짜/짧은 흐름 → 대표 → 업계 기사 → 필요한 상담 → 팀 1분 요약/공유/PDF.

제목·짧은 요약·발행사/날짜·원문 기본 노출. 긴 근거·영향·상담은 펼침. 모든 기사에 TODAY ACTION·7축 장문·타임라인·교육 과제를 강제하지 않는다.

| 상담 항목 | 내용 |
|---|---|
| 관련 대상 | 실손 세대·갱신 예정자·청구자·은퇴 준비자 등 일반 대상군 |
| 쉬운 설명 | 확인된 사실을 고객 언어로 전달 |
| 먼저 확인 | 가입 시점·세대·약관·갱신 조건·서류 |
| 피할 표현 | 무조건 지급/전환 유리/확정 보험료 인상 등의 단정 |
| 다음 단계 | 실제 등록되고 사용자에게 허용된 WORKSPACE 도구 1~2개 |
| 복사 | 고객 설명용·내부 준비용 구분, 저장 문구 재사용 |

| communication_state | 고객 설명용 복사 |
|---|---|
| customer_ready | 검증 문구 허용 |
| consultation_reference | 먼저 확인할 조건 확인 후 허용, 미확인 시 내부 준비용 |
| internal_check | 차단 |
| do_not_mention | 차단 |
| not_applicable | 억지 문구 생성하지 않음 |
| 누락/알 수 없음 | 차단·관리자 확인 |

고객 ID/계약 자동 조회·자동 발송 없음. AI 임의 도구 경로 금지, 기존 Tool Registry/allowed_tools 재사용. 복사·펼치기 때 AI 호출하지 않는다.

## 6. 고객 보험 생활정보

전체 업계 뉴스는 내부. 고객은 생활 관련성이 있고 중립적·검증된 외부 문구가 있는 기사만 읽는다. 적격 정보가 없으면 섹션을 숨기며 억지로 채우지 않는다.

상담 상태와 공개 정책은 별개다. not_applicable이라도 중립 보험 정보는 외부 Gate 통과 시 가능. do_not_mention·미확정 고위험 고객 문구는 차단한다.

내부 상담/영업전략/대상 고객 목록/점수/도구/운영 로그는 외부 DTO 제외. 정상 승인된 외부 본문을 기본 공유 구성으로 사용해 매일 기사별 편집을 강제하지 않는다.

링크 생성 계정의 이름+실제 직책을 본문/OG/고객 PDF에 표시하고 화랑은 보조 브랜드. 공개·정정·회수·캐시·비로그인 계약은 ENGINE을 따른다.

## 7. PDF·이력

내부 PDF는 업계 기사와 필요한 상담. 고객 PDF는 승인 생활정보만. 같은 Snapshot, 별도 AI 없음.

한글 폰트·본문 크기·여백·원문 링크·자연스러운 다중 페이지. 과거 고정 4~6페이지 기준을 맞추려고 글자 축소/내용 추가하지 않는다. 웹/각 PDF 상태 분리. 최근 30일+날짜 검색+판본/정정/숨김 이력.

## 8. 자체 검수

Codex: 다양한 업계 발행사·기관 편중·보험 과잉 라우팅·KST 날짜·중복, 해킹/유출·예고/시행·보험료 대상 표현, 비관련 상담 억지 생성 방지, 상태별 복사/도구 권한, 외부 DTO/이름/회수, 모바일/큰 글자/PDF·원문.

사용자는 실제 고객 표현 적합성을 최종 확인 B/C에서 묶어 확인한다. 일반 반복 회귀는 Codex가 담당한다.
