# 화랑 종합뉴스 명세 — NEWS V1.8.0

- 2026-10-08 / Asia/Seoul.
- 범위·수량·일정은 BRIEFING_V1_IMPLEMENTATION_SCOPE.md, 데이터·공유·권한은 BRIEFING_ENGINE_SPEC.md를 따른다.
- 현재 구현 완료가 아닌 개발 기준이다.

## 1. 목적·분야

아침 비서 공유 뉴스처럼 전날·당일 중요한 사건을 여러 분야에서 짧게 읽고 원문으로 연결한다. 공공기관 보도자료만 모으는 기능으로 대체하지 않는다.

| 분야 | 포함 |
|---|---|
| 정치·행정 | 주요 정책·선거·국회·외교·사회적 의미가 큰 정치 사건 |
| 사회·안전 | 재난·사고·범죄·판결·교통·통신 이슈 |
| 국제·안보 | 큰 국제 이슈와 한국에 영향 있는 통상·안보·분쟁 |
| 경제·생활 | 물가·주거·대출·고용·소비자 관련 변화 |
| 보건·복지·교육 | 의료·감염병·연금·돌봄·입시 |
| 과학·기술·산업 | 우주·AI·반도체·기업·보안 |
| 생활·날씨 | 출퇴근·안전·일상에 중요한 기상·생활 정보 |

단순 광고·기업 홍보·연예 사생활·선정적 가십·검증 안 된 SNS는 제외한다. 일반 스포츠 결과는 기본 제외하되 사회적 의미가 큰 문화·스포츠 사건은 가능하다. 공식 문서가 없다는 이유만으로 중요한 정치·사건 보도를 모두 배제하지 않는다.

## 2. 수량·선정

**총 최대 10건, 대표 핵심 최대 1건 포함**. 대표가 있으면 1+9, 없으면 관련 최대 10. 적격 기사 부족 시 실제 수량만 표시한다.

관련 뉴스는 대표 사건의 유사 기사 묶음이 아니라 서로 다른 당일 사건이다. 동일 사건의 출처는 한 카드에 모은다. MARKET 등과 겹치면 통합 고객 화면에서 중복 계산하지 않는다.

내부 점수·CORE/LIGHT는 저장·선별 호환용이며 고객에게 숨긴다. 주제·발행사 다양성은 정렬 보조다. 중요한 사건을 강제 quota로 누락하거나 숫자를 채우려 저품질·과거 기사를 넣지 않는다.

처음 3건만 보여주는 구성을 기본으로 하지 않는다. 제목과 짧은 요약은 목록에서 바로 읽는다.

## 3. 날짜·수집

구간은 **전날 00:00 KST부터 해당 생성의 수집 마감까지**. 정규 마감 목표 07:30, 공개 목표 08:00. 휴일도 같은 구간이다.

원문 발행일, API 제공일, 수집일을 구분한다. 표준 meta/JSON-LD/time으로 날짜를 보강하고 Crawled·retrieved를 발행일로 쓰지 않는다. 날짜 미확인·구간 밖·새 사실 없는 과거 재보도는 정상 목록에서 제외한다. 배경은 날짜 표시된 상세 근거로만 연결한다.

허용된 종합·통신·방송·경제 언론 RSS/피드 → 필요한 원문 보강 → 부족 분야·중요 검증에 기존 web_search. 공공기관 자료는 정책·시행일·수치 검증에 활용한다.

수집 endpoint와 실제 publisher를 구분한다. 기관 1곳의 성공만으로 종합뉴스 Coverage를 healthy로 판단하지 않는다. 편중·누락을 진단하고 수집 실패와 실제 뉴스가 적은 날을 구분한다.

네이버 API의 변경 경로·AI 이용 조건 확인 전 기본 AI 원천으로 채택하지 않는다. Google News 비공식 RSS는 공식 API의 안정성·권한 보장으로 취급하지 않는다. 두 서비스는 필수 의존성이 아니다.

## 4. 사실·요약

각 기사 제목+사실 중심 1~2문장+발행사·발행일+원문 하이퍼링크.

- 신뢰 매체의 명확한 보도는 사용할 수 있으며 매번 공공기관·복수 출처를 강제하지 않는다.
- 주장/계획/발의/의결/시행, 수사/혐의/기소/판결 확정을 구분한다.
- 중요한 상충·고위험 내용은 추가 확인하거나 격리한다.
- 원문에서 확인하지 않은 금액·인원·시행일·원인을 추정하지 않는다.
- 정치 성향 평가·과장·공포·불필요한 피해자 개인정보를 넣지 않는다.
- 일반 뉴스에 보험 판매·상담을 억지 연결하지 않는다.
- 전문·사진 재게시·유료벽/차단 우회 없이 짧은 독립 요약과 원문 링크를 제공한다.

## 5. 화면

날짜·기준시각·공개 상태 → 대표 1개 → 나머지 기사 → 과거/공유/PDF.

대표도 짧은 요약을 기본 노출하고 필요한 의미·근거만 펼친다. 모든 제목/원문 버튼은 저장된 http/https URL에 연결한다. 모델 URL 생성 금지, HTML escape·안전한 새 탭 처리.

본문 16~18px·넉넉한 행간·큰 글자·360~430px 가로 넘침 없음. 내부 운영 상태는 관리 영역에 두고 고객 독서 화면에는 제외한다.

## 6. 고객·PDF·이력

정상 published+validation=ok+외부 QA+공유 허용 본문을 재사용한다. 고객 상담 not_applicable만으로 중립 뉴스를 차단하지 않는다.

발신자는 링크 생성 계정의 등록 이름+실제 직책. 본문/OG/고객 PDF에서 날짜·판본·발신자 일치, 작은 화랑 보조 표기. 이름 중심 대형 카드를 기본으로 하지 않는다.

내부 점수·상담·도구·비용·로그·권한·키는 외부 DTO에 넣지 않는다. 오늘 지연 시 이전판을 실제 날짜와 “이전 브리핑”으로 표시한다. 정정은 새 Revision과 정정시각, 회수/숨김은 서버 Gate를 따른다.

PDF는 같은 Snapshot, 별도 AI 없음. 자연스러운 다중 페이지·한글 폰트·충분한 글자·여백·제목/요약 동시 배치·출처/원문 링크. PDF 실패와 웹 게시 상태는 분리한다. 최근 30일 기본 이력+날짜 검색+판본/정정/숨김 유지.
