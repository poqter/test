# 화랑 브리핑 배포 준비본 — 2026-10-13

버전: 1.11.0-release / 기준 코드: 이미 적용한 1.10.0-launch, commit 12924256889e43093db62927dbb08bd08ea0be2e.
이 문서는 첨부한 오래된 1.7.2 체크포인트보다 이후의 실제 코드 및 이번 대화의 확정 결정을 따른다.
이번 작업은 파일 제작과 로컬 검증까지다. 운영 DB 쓰기·프로젝트 OpenAI 호출·GitHub 쓰기·배포 0회.

## 구현 내용

1. 경제·금융은 기사 중심 완성본. 지표 공급원 미설정 차단 제거, 공급원 호출/구독 비용 없음.
2. 뉴스 최대 10, 경제 최대 8, 보험 기존 분석 호환 상한 15. 적격 기사 부족 시 실제 수량 게시, 0건/검증 실패는 보류.
3. 수집된 사건의 발행사/섹션을 균형 있게 분석 입력에 배치. 보험 상담을 일반 뉴스에 강제하지 않고, 분석 응답에 모든 입력 사건의 간결한 결과를 요구한다.
4. 제목·요약·배경·영향·출처를 바로 읽는 B안. 큰 글자, 모바일 카드, 오늘/지난 브리핑과 작은 운영 설정 경로.
5. 같은 날짜의 통합 공유 기본. 선택 영역 제외, 사건/원문 URL 중복 제거, 고객 적격 보험 생활정보만 포함.
6. 공유 버튼을 항상 표시하고, 사용 불가 시 실제 원인과 해결 경로 안내. 서버 계정의 이름·실제 직책이 HTML/OG/PDF에 일치.
7. 조직 최초 승인 이후 게시본의 자동 품질 확인으로 공유 활성화. 일일 판본별 수동 승인 없음.
8. 매일 예약 생성·게시, 최대 1회 복구, 완료/응답 불명확 작업 중복 유료 호출 방지. 이전 실패 기록만으로 현재 check가 실패하던 결함 수정.
9. 오늘의 완성 통합본이 없으면 최근 동일 날짜 정상 통합본을 날짜와 함께 제공. 오늘/어제 내용을 혼합하지 않음.
10. 정정 및 중요 공식 발표 추가는 새 판 저장. 정규 기사 quota와 별개로 중요 추가를 표시. 기존 링크에서 최신 본문/PDF 제공, 다운로드된 파일은 자동 변경되지 않음.
11. 어느 공유 구성요소든 비공개되면 HTML/PDF/미리보기 전체 접근 차단. 고객 공유 취소·만료·조직 승인 OFF·계정 비활성도 차단.

## 예약 시각 (한국시간)

06:30 준비(유료 호출 없음), 07:00 경제 생성(수집 마감), 07:30 경제 게시 및 종합뉴스/보험 생성(수집 마감), 08:00 게시, 08:10 복구 최대 1회 및 게시 확인.
GitHub Actions 예약은 플랫폼 사정에 따라 지연될 수 있다. 화면은 실제 게시 날짜/수집 기준을 표시한다.
기존 shadow → 자동 공개 전환의 3영업일 자동 품질 관찰은 유지한다. 날짜별 사용자 승인을 요구하지 않으며, 통과 일수는 운영 설정에서 확인한다.
정규 생성 외 장중 자동 유료 재생성은 추가하지 않는다. 중요한 공식 발표는 관리자 추가 경로로 반영한다.

## 적용 순서

### 1. 파일 교체

변경파일 ZIP의 경로 그대로 기존 저장소에 덮어쓴다. 통파일 ZIP은 전체 코드 보관/비교용이며, 기존 운영 자료를 불필요하게 교체하지 않도록 변경파일 적용을 권장한다.
계정·비밀번호·개인 데이터·Supabase 데이터는 ZIP에 없으며 기존 DB를 초기화하지 않는다.
GitHub에 파일 업로드와 실제 앱 반영은 사용자가 진행한다. 이번 파일은 원격에 반영되지 않았다.

### 2. DB 추가 변경

현재 이미 21번까지 적용된 DB에서 `supabase/migrations/22_Briefing_Article_Release.sql`만 Supabase SQL Editor에 붙여 실행한다.
기존 16~21번을 초기화/재실행하지 않는다. 22번은 정책 승인 값을 자동으로 켜지 않으며 기존 계정/기록을 삭제하지 않는다.
이 변경이 필요한 이유: DB에도 남아 있는 지표 필수 게시 Gate 제거, 통합 공유의 구성요소별 접근 차단, 정정 후 같은 링크 갱신.
운영 DB에 별도의 22번 변경이 이미 있다면 내용 확인 후 이번 변경을 충돌하지 않는 다음 migration 번호로 보관한다. SQL 함수의 동작은 파일 번호와 무관하다.

### 3. 기존 설정 유지 및 앱 재시작

기존 SUPABASE_URL, SUPABASE_SECRET_KEY, OPENAI_API_KEY, BRIEFING_DISCOVERY_MODEL/BRIEFING_ROUTINE_MODEL,
BRIEFING_PUBLIC_BASE_URL, 기존 언론 피드 설정은 유지한다. 새 공급원 키/구독/결제는 필요하지 않다.
BRIEFING_MARKET_PROVIDER/FMP/ECOS/관측값 설정은 현재 생성에 사용하지 않는다. 제거 여부와 무관하게 정상 생성 가능하다.
현재 이미 연결한 Cloudflare 고객 읽기 페이지는 worker 변경이나 재배포가 필요 없다. schema hwarang-share-v3를 유지한다.
STAGE1_CHANGED_FILES.json도 함께 교체한 뒤 Streamlit 앱을 재시작한다.

### 4. 최초 운영 승인 (최고관리자)

브리핑 센터 → 운영 설정 → 게시·고객 공유 설정에서 다음 세 항목을 한 번 켜고 저장한다.
- 매일 자동 생성
- 관찰 3영업일 이후 영역별 자동 공개
- 검증된 고객용 본문 공유 허용
이 설정은 조직에 한 번 적용한다. 기존 전체 AI 스위치가 OFF이면 생성은 중단되므로, 생성 운영을 시작할 때 기존 전체 AI도 ON 상태여야 한다.
이 안내는 적용 후 사용자가 실행할 단계이며, 이번 작업 중 실제 승인 값을 변경하지 않았다.

### 5. 사용 시작

오늘 브리핑에서 영역을 선택해 읽고 통합 공유 링크를 만든다. 문구/링크를 복사해 카카오톡·문자로 직접 전송한다. 메시지 자동 발송은 없다.
공유할 영역은 기본 전체이며 원하는 영역을 제외할 수 있다. 고객 적격 보험 내용이 없으면 해당 영역은 포함하지 않는다.
저장된 정상 게시본이 아직 없다면 최초 생성/관찰 통과 전까지 게시 전 초안은 운영 설정에서 읽을 수 있다.
기존 완료 일일 작업은 다시 결제해서 전체 생성하지 않는다. 새 정책은 다음 정규 생성부터 적용하며, 같은 날짜 실패 작업은 저장된 checkpoint에서 1회 복구한다.

## 검증과 남은 실제 환경 확인

자동 테스트, 고객 HTTP 경로, 별도 PostgreSQL 엔진의 migration 실행, 직원/고객 모바일 및 PDF 렌더링을 확인한다. 결과는 VALIDATION_20261013.md 참조.
운영 환경에서 SQL 적용·예약 실행·실제 메신저 표시까지 실행한 것은 아니다. 실제 하루 기사 수/지연/청구액을 로컬 검증 결과로 보장하지 않는다.
적용 후 새 버전 진단이 일치하는지, 최초 공유 링크가 휴대폰에서 열리는지만 한 번 확인하면 된다. 매일 검수·테스트를 다시 요구하는 운영으로 만들지 않는다.

## 복구

문제 발생 시 운영 설정에서 자동 생성/게시/공유를 끄고 기존 정상본을 유지한다. 코드만 이전 보관본으로 되돌릴 수 있다.
22번은 추가 테이블과 함수 교체를 포함하므로 이전 코드로 되돌렸다는 이유로 DB를 초기화하거나 새 구성요소 기록을 삭제하지 않는다. 전체 조직 공유 OFF는 기존 링크까지 닫는다.
