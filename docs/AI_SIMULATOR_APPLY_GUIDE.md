# 화랑 AI 상담 Studio 1.13.0 적용 안내

## 현재 상태

1.12.7 CATCHUP 전체본을 기준으로 만든 소스 수정본입니다. 운영 GitHub·Streamlit·Supabase는 변경하지 않았습니다. 운영 API 키가 이 작업 환경에 없어서 실제 유료 호출은 0회입니다. API 연결 코드와 로컬 모의 검증 완료는 실제 계정 연결 성공을 의미하지 않습니다.

브리핑 엔진·예약 workflow·고객 공개 Worker는 1.12.7 그대로입니다. 기존 규칙 기반 시뮬레이터, 로그인, 세션, 조직 권한, 기존 학습 기록 및 크레딧/Voice 원장은 보존합니다.

## 적용 순서

1. 기존 소스와 운영 DB를 백업합니다. 현재 1.12.7이면 변경본을 저장소 루트에 덮어씁니다. 다른 기준 버전이거나 별도 수정이 있다면 전체본을 무조건 덮어쓰지 않고 비교해야 합니다.
2. Supabase SQL Editor에서 `supabase/migrations/23_AI_Simulator_Studio.sql`을 **한 번** 실행합니다.
3. 이어서 `supabase/migrations/24_Voice_Request_Settlement_Fix.sql`을 **한 번** 실행합니다. 기존 01~22 SQL을 다시 실행하지 않습니다.
4. WORKSPACE와 ACADEMY 앱이 같은 최신 저장소를 사용하도록 배포합니다. ACADEMY 진입점은 기존 `academy_app.py`입니다. 기존 DB 연결 Secrets와 외부 앱 URL은 유지합니다.
5. **ACADEMY 앱의** Streamlit Secrets에 아래 설정을 추가합니다. WORKSPACE에만 등록한 키는 독립 ACADEMY 앱에 자동 전달되지 않습니다. 기존 최상위 OPENAI_API_KEY가 있으면 재사용합니다. 키를 ZIP·GitHub·채팅에 넣지 않습니다.
6. 관리자센터에서 AI 서비스와 Text를 켜고, 필요한 경우 Voice·평가도 켭니다. 사용자의 `academy.simulator`, `academy.voice_simulator`, `academy.formal_ai_assessment` 권한과 Training Credit·Voice 잔여량을 확인합니다. 이번 SQL은 이 스위치나 기존 계정 권한을 자동으로 바꾸지 않습니다.
7. ACADEMY의 **AI 상담 Studio 시작**으로 접속합니다. 먼저 텍스트 자유 연습 한 회차를 실행하고, 고객 답변·피드백·원장·비공개 조회를 확인한 뒤 음성을 시험합니다.

```toml
# 기존 최상위 설정이 있다면 중복해서 작성하지 않습니다.
OPENAI_API_KEY = "실제 키는 Streamlit Secrets에서만 입력"

[simulator_ai]
customer_model = "gpt-4.1-mini"
coach_model = "gpt-4.1-mini"
evaluator_model = "gpt-4.1-mini"
transcription_model = "gpt-4o-mini-transcribe"
speech_model = "gpt-4o-mini-tts"
customer_credits = 1
coach_credits = 1
evaluator_credits = 5
timeout = 60
```

`[simulator_ai] api_key`로 별도 키를 둘 수도 있습니다. 텍스트 역할은 기존 DB 모델 정책에 값이 있으면 그 설정을 우선합니다. 관리자센터의 AI 상담 모델·차감 설정에서 변경하면 기존 CUSTOMER/COACH/EVALUATOR 모델 정책과도 연결됩니다. 기존 GPT-Live용 정책은 보존하며, 이번 음성은 녹음→인식→텍스트 고객 응답→음성 생성 방식입니다.

## 이용량 기준

기존 월 기본 지급, 구매분 우선순위, 관리자 조정 출처와 Ledger/Audit 체계는 변경하지 않았습니다. 기존 코드에는 실제 호출별 환산율이 확정돼 있지 않아 이번 연결의 초기 단위를 설정으로 분리했습니다.

| 처리 | 초기 차감 |
|---|---:|
| 고객 답변 1회 | 1 Credit |
| 단계별 힌트 묶음 생성 | 1 Credit |
| 자유 연습 종료 피드백 | 1 Credit |
| 공식 평가 피드백 | 5 Credit |
| 음성 인식·음성 생성 | 각각 실제 처리 길이를 초 단위 올림하여 Voice 차감 |
| 같은 힌트 펼치기·저장 결과 재조회·메모리에 남은 음성 재생 | 추가 생성 없음 |

되돌리기는 이미 사용한 Credit·Voice를 환급하지 않습니다. 다시 답변하면 새 고객 응답에 표시된 단위가 적용됩니다. TTS는 최대 180초를 먼저 예약하고 실제 생성 길이만 차감합니다. 따라서 180초 미만의 Voice 잔여량에서는 음성 생성이 제한될 수 있습니다. API 원가와 서비스 Credit은 다른 값입니다. 원가 미확인은 0원으로 기록하지 않습니다.

## 사용 흐름

- 자유 연습/공식 평가 → 집중 연습/전체 상담 → 시작 장면 → 난이도·고객 → 텍스트/음성/혼합.
- 전체 상담은 같은 가상 고객과 전화 약속·첫 상담·보장분석·가입 제안·거절 대응을 이어갑니다. 선택한 시작 장면 이후의 단계만 진행합니다.
- 고객의 가족·보험·경제 정보는 고정하고 감정·신뢰·공개 정보만 변화시킵니다. 고객의 거절은 모든 단계에서 발생할 수 있습니다.
- 자유 연습은 힌트 단계 펼치기, 이전 장면 복원, 같은 고객/새 고객 재도전, 취약 장면 재훈련을 제공합니다. 공식 평가를 재훈련하면 원본은 유지하고 새 비공개 자유 연습을 만듭니다.
- 음성은 녹음을 종료한 후 인식하고, 사용자가 인식 문장을 확인·수정해 제출합니다. 음성 모드에서는 고객 답변 자동 생성·재생을 선택할 수 있습니다. 브라우저 자동재생 제한이 있으면 재생 버튼을 누릅니다.
- 최초 고객 답변으로 목소리를 미리 들을 수 있습니다. 원본 녹음·생성 음성은 학습 DB에 저장하지 않습니다. 현재 세션 메모리에는 최근 생성 음성 최대 6개가 남습니다.
- 음성 인식/재생의 장치별 작동, 실제 응답 속도·자연스러움, 모바일 시각 검수는 운영 확인 대상입니다.

## 평가·종료·공유

- 항목: 요구 파악, 경청·반응, 설명 정확성과 명료성, 우려 대응, 다음 단계 합의. 상담 단계별 우선순위가 다릅니다.
- 실제 발화 인용을 검증합니다. 근거가 없는 항목은 평가 불가입니다. 음성 전달력은 공식 점수에서 제외합니다.
- 배점/합격선 검증 전에는 종합점수·합격 판정을 산출하지 않습니다. 이는 합의된 보류 정책입니다.
- 명확한 진행 불가 응답이 연속 3회이고 사전 경고 및 맥락 재확인이 있을 때 종료합니다. 1회 되묻기 → 2회 경고 → 3회 확인 후 종료. 애매한 판정과 서툰 답은 자동 이탈 처리하지 않습니다. 정상 복귀 시 연속 횟수를 초기화합니다.
- 초기 단계 한도: 전화 12회 / 첫 상담 20회 / 보장분석 20회 / 가입 제안 16회 / 거절 대응 12회. 시작 후 표시하며 3회 남았을 때 알립니다. 실사용 길이에 따른 후속 조정 대상입니다.
- 관리자는 권한 범위 내 자유 연습 참여 횟수·완료 여부만 기본 조회합니다. 공유 대상·항목은 기본 미선택이며 미리보기 후 공유합니다. 공유 철회는 이후 조회를 차단합니다.
- 공식 평가 결과는 기존 조직 권한 내 담당자가 조회합니다. 판정 확인 요청과 답변은 기록으로 남으며 메시지나 이메일을 자동 발송하지 않습니다.

## 응답 불명·중단 처리

외부 호출은 자동 재시도하지 않습니다. 요청을 DB에서 독점 예약하고 응답을 저장한 뒤 원장 정산과 대화 반영을 합니다. 완료한 요청은 재사용합니다. 타임아웃 등 처리 여부 불명은 새 회차로도 우회하지 못하게 보류합니다.

관리자센터의 AI 상담 요청 확인에서 요청 식별자와 외부 처리 내역을 대조합니다. 단순히 다시 실행하려고 잠금을 풀지 않습니다. 10분 이상 경과한 요청에 대해서만 확인 근거를 남기는 조정이 가능합니다. 이미 원장이 만료되었거나 음성 처리 완료 후 실제 길이를 확인해야 하는 건은 별도 정산 확인이 필요합니다.

## 검증 범위

Python 회귀 273개(기존 237 + Studio 36), 공개 페이지 검사 39개, 로컬 PostgreSQL 호환 엔진 DB 검사 29개, Streamlit 화면 흐름 검사를 수행했습니다. DB 검사는 가상 계정과 Supabase Auth 스텁을 사용하며 운영 DB를 건드리지 않았습니다. 브리핑 관련 파일은 기준본과 바이트 단위로 동일함을 확인합니다.

DB 검사에서 기존 음성 정산 함수의 `balance_seconds` 출력 변수/열 이름 충돌을 재현하고 24번 보정문으로 수정했습니다. 원장을 초기화하거나 기존 migration을 수정하지 않습니다.

실제 유료 API, 실제 운영 DB migration, 배포 화면, 마이크·스피커 장치, 모바일 픽셀 검수는 미실행입니다. 자동 발언 종료 감지·무확인 자동 전송은 합의한 안정성 확인 전 보류 정책에 따라 활성화하지 않았습니다. API 응답 품질은 실제 회차로 확인해야 합니다.
