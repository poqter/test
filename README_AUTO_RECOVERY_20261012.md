# 화랑 브리핑 자동 생성 복구 · 2026-10-12

최신 전체 소스입니다. 이전 LAUNCH1 통파일과 피드 버튼 수정본을 포함합니다. 현재 GitHub main의 366개 파일을 전부 비교한 기준 커밋은 `09d745a2936a963b8944b7e2753c3572ad0fe689`입니다.

## 실제 운영 상태

- 전체 AI 활성화가 저장됐습니다. 학습 AI와 브리핑 AI가 함께 켜졌습니다.
- 매일 자동 생성 정책은 켜진 상태로 저장했습니다.
- 고객 읽기 페이지 연결과 언론사 RSS 8개 연결은 실제 운영 앱에서 확인했습니다.
- 오늘 실제 생성 1회는 검색 2개 요청과 종합뉴스 분석 1개 요청까지 실행했습니다. 사용량 기록이 확인됐으며 같은 생성을 반복하지 않았습니다. 최종 청구액은 여기서 확인하지 못했습니다.
- 모델이 20개 후보 중 6개만 분석해 반환하자 기존 코드가 전체 실패로 처리했습니다. 이 오류의 원인은 휴일이나 뉴스 부족이 아닙니다.
- 실제 응답을 수정하거나 새로 호출하지 않고 그대로 재검증했습니다. 수정본은 반환된 6개를 검증하고 누락된 14개는 제외합니다. 운영 DB에 새 브리핑을 저장했다는 뜻은 아닙니다.
- **수정본 배포는 아직 완료되지 않았습니다.** GitHub 연결의 코드 쓰기는 403으로 거절됐습니다.
- GitHub 예약 실행 로그에서 OPENAI_API_KEY와 모델 변수가 비어 있었습니다. 기존 Supabase 연결 값은 확인됐습니다.
- 자동 공개와 고객 공유 허용은 꺼져 있습니다. 자동 공개 설정 저장은 자동 승인 검토에서 별도 승인이 필요하다는 이유로 거절됐습니다.
- 경제·금융 6개 지표는 공급원 연결이 남아 있습니다. 종합뉴스·보험업계 생성은 이 설정과 독립적입니다.

## 수정한 내용

1. GitHub의 빈 휴일 추가 설정을 빈 목록으로 처리해 예약 준비 오류를 해결합니다.
2. AI 요청에 전체 후보 개수·후보 키·분류 목록을 명시합니다. 최종 기사 선정은 앱이 합니다.
3. 유효한 부분 응답은 사용합니다. 분석되지 않은 기사에 요약을 만들어 붙이지 않습니다.
4. 중복 키·알 수 없는 기사 키·잘못된 분류·빈 요약·불완전 응답은 계속 차단합니다.
5. 사용량이 기록된 분석 응답을 저장해 재개 시 같은 분석을 다시 호출하거나 사용량을 중복 기록하지 않습니다.
6. 이전 버전의 실패 진단에만 저장된 오늘 분석 응답도 원래 후보 키가 일치할 때 재사용합니다.
7. 실패 후 `중단된 브리핑 이어서 생성` 버튼을 보여줍니다. 하루 최초 1회와 복구 1회, 과금 불명확 시 중단하는 제한은 유지합니다.
8. GitHub 모델 변수 누락 시 기존 앱의 실제 요청에서 확인한 `gpt-6-luna`를 사용합니다. 등록된 변수가 있으면 그 값을 우선합니다. 모델명을 따로 입력할 필요를 줄인 것입니다.

## 한 번만 필요한 적용

1. 이 통파일을 기존 프로젝트에 덮어써서 GitHub main에 반영합니다. `app.py`가 있는 저장소 루트가 기준입니다. 폴더 경로와 `.github` 폴더를 보존합니다. 코드와 `STAGE1_CHANGED_FILES.json`은 함께 반영합니다. 기존 자료·프로젝트 MD·회원 데이터를 삭제하지 않습니다.
2. GitHub `poqter/test` → Settings → Secrets and variables → Actions → Secrets → New repository secret에서 `OPENAI_API_KEY`를 등록합니다. 값은 현재 Streamlit에 등록된 기존 OpenAI API 키입니다. **소유자가 직접 입력하며 채팅에 보내지 않습니다.** 별도 가입이나 새로운 유료 서비스 구입은 필요하지 않습니다.
3. 배포 후 앱의 `배포 진단 · API 호출 없음`에서 `release_patch_id: launch1-analysis-recovery-20261012`, `code_matches_release: true`를 확인합니다.
4. 오늘 실패한 DAILY 작업에 복구 한도가 남아 있다면 `중단된 브리핑 이어서 생성`으로 이어갑니다. 이미 받은 NEWS 응답은 재사용하며 아직 실행하지 않은 INSURANCE 분석에는 API 요금이 발생합니다. 원래 후보 키가 일치하지 않거나 사용량 확인이 안 되면 유료 재호출 없이 중단합니다. 이미 완료됐다면 다시 생성하지 않습니다.
5. 생성된 관리자 초안의 실제 저장·기사 수·원문 링크·요약·사용량 기록을 검수합니다. 이 실제 검수는 수정본 배포 후 수행해야 합니다.

기존 Migration 19/20/21이 적용된 상태를 사용합니다. SQL을 다시 적용할 필요가 없습니다. 초기화용 SQL은 다시 실행하지 않습니다. 고객 읽기 페이지도 이번 수정 때문에 다시 배포할 필요가 없습니다.
